# Contributing to VanStock

Thanks for contributing. Please use an issue to discuss substantial changes
before investing significant implementation effort.

## Before opening a pull request

- Keep each pull request focused on one user-visible change or one technical
  concern.
- Never include credentials, production configuration, customer data, logs,
  database dumps, screenshots containing personal information, or generated
  build artifacts.
- Add or update tests when the project has a suitable test target.
- Update documentation when behaviour, setup, or an API contract changes.
- Run the checks relevant to the changed area before requesting review.

## Pull requests

Describe the problem, the chosen solution, verification performed, and any
deployment or migration impact. Do not include security-sensitive details in a
public issue or pull request; follow [SECURITY.md](SECURITY.md) instead.

By submitting a contribution, you confirm that you have the right to submit it
under the project's AGPL-3.0-or-later license.
