# Security policy

## Supported versions

Security fixes are prepared for the latest released version. The development
branch may receive a fix first when a coordinated release is required.

## Reporting a vulnerability

Do not disclose vulnerabilities, credentials, production URLs, personal data,
or proof-of-concept exploits in public issues.

Use GitHub Private Vulnerability Reporting for this repository. Include a clear
description, affected component and version, reproduction steps, impact, and
any suggested mitigation. If private reporting is not enabled, contact a
repository maintainer privately through GitHub and ask for a secure channel.

Reports are acknowledged as soon as reasonably possible. No response-time or
remediation-time SLA is promised.
